# Consoleの曲保存・受付復旧を保持する

既存Consoleの再ビルドでも音楽連携の修正を失わないための組み込み資料です。Consoleの土台は `b5b3b38`、確認した統合版は `9e54f67fdf4a66feb91fb2b7ee65ff05e2188d2d` です。現在のConsoleに別の修正がある場合はそれを保持して統合します。

- `music_bridge.rs` をConsoleの `src/music_bridge.rs` に配置し、ConsoleのRust editionで整形します。既存Host/Origin保護と常駐の起動方法を維持します。
- `receipts.patch` は既存Consoleの `src/agent.rs` とCargo定義への変更です。`todo_receipts.rs` はConsoleの `src/todo_receipts.rs` に配置します。共有ToDo本体のソースやCLIを変更するものではありません。
- Consoleの再ビルド元へ統合してから、別モデル確認と検査、既存の定期タスクによる配備を行います。実画面の確認は別の受入条件です。

新規受付は共有ToDoの既存Rustライブラリーで、項目と元の要求を同じOSロック内・1回の原子的保存で確定します。同じ受付IDで異なる内容やプロジェクトを送ると409になります。Block/Doneでメモが変わっても、元の受付情報は保持されます。

旧版の確定した受付ファイルは要求と対象を照合して使用します。変更できるメモだけが残る旧項目は、自動的に採用したり再登録したりせず409で保持します。旧記録の存在確認に失敗した場合も、新規項目を作らず503になります。既に失われた旧情報を復元できるという保証ではありません。

PC共通の依存先は `cc-todo` 0.1.0（`../rs/cc-todo`）です。このPCの既存コードを再利用し、Cargo.lockに固定します。確認した `src/lib.rs` のSHA-256は `22D89EC4510AC8295F54701D04ABEBB8959798B3F855A9B968219D235E66BE39` です。公開の再配布ライセンスは宣言されていません。第三者の納品物へは同梱しません。新しい外部パッケージの取得・APIキー課金・生成は必要ありません。

検査は実曲や実際の生成を使わず、合成音源と専用の共有ToDoストアで行います。受付応答の喪失、再起動、メモの更新、異なるプロジェクト、識別子を含む本文、属性確認の失敗で、項目が増えたり受付情報が書き換わったりしないことを確認します。状態ストアに書くため、実運用のストアを試験対象にしません。
