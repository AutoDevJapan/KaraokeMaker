# メタル・速いラップの本人曲で音質と字幕を改善する

2026-10-04 18:46〜18:47 JSTの指摘「音質が悪く字幕が見えない」を受け、麻臭 a.k.a. mashの曲へ題材を変更した。前のCC0試験はこの用途の合格と扱わない。ココナラ調査は後で使うメモとして保持し、出品しない。

## 題材と原本

- メタル: [The Hope III - The Nothing](https://www.youtube.com/watch?v=gn0wHbHr_TU)。歪んだギター、速いドラム、叫び声。
- ラップ: [My Universe](https://www.youtube.com/watch?v=CR-eDcOXlHk)。速い日本語、低音、英語。

[本人のチャンネル](https://www.youtube.com/@makhmeto)は UCzQBBiceYneATFx2VTsJ_Wg。本人の作品の内部取得を明示許可された。公式Windows版yt-dlp 2026.08.19でOpus/48kHzと字幕確認用動画を取得し、30〜58秒の28秒を切り出した。曲の説明の歌詞を正本にした。YouTubeで既に圧縮された音を、48kHz/24bit出力で元の未圧縮品質へ戻せるとは扱わない。

原本、歌詞、モデル出力、測定JSON、画像、短い動画はGit対象外の evidence/mash-20261004 に保持。原本を上書きせず、外部AIへ送らず、動画サイトへ投稿しない。依頼されたDiscord製品スレッドに短い動画と画像だけ直接添付した。

## 比較した分離方法

時間は28秒の分離とWAV/MP3/MP4出力を含む。字幕の手直し時間は含まない。

| 方式 | メタル 秒 | ラップ 秒 | 判定 |
| --- | --- | --- | --- |
| HTDemucs standard / Rust・Vulkan | 37.81 | 48.89 | 従来の比較対象 |
| HTDemucs FT / 歌声を原音から引く | 45.84 | 28.18 | 比較用として保持 |
| Mel-Band RoFormer FP32 / DirectML | 446.63 | 未実行 | この方法は待ち時間が長い |
| Mel-Band RoFormer FP16 / CUDA | 15.90 | 65.72 | このPCの標準方式 |

RTX 5090、Ryzen 9 9950X3D、FFmpeg 8.0.1で測定。ラップのCUDA試験は初回準備を含み、最初の8秒区間は48.78秒、その後は0.12〜0.17秒。後のメタルは準備済みで最初2.02秒、その後0.11〜0.12秒。共有PCの実測であり、全てのPCや曲の速度保証ではない。

STFTまでグラフに含むsmank版は425秒で最初の区間を返せず中止した。半精度版のDirectML 1.22.1/1.24.4は初期化に失敗した。失敗した方式を成功として表示せず、CUDAの構成を確認して採用した。MDX-Net・BS-RoFormerの全候補と、全アンサンブルを実測したわけではない。世界で一番良いモデルとは説明しない。

標準方式は歌声だけを推定し、48kHzの原音から差し引く。44.1kHzサンプリングで扱えない22.05kHz超の帯域も原音から残せるが、誤って歌声と推定されたギターを必ず復元する方式ではない。

## 音量・帯域・加工

キー0・速度1ではRubber Bandとリミッターを省く。浮動小数点の段階でtrue peakを測り、必要な分だけ音量を下げてから24bitへ変換する。クリップした波形から音量を下げる方法は避ける。WAVは48kHz/24bit、MP3は320kbps、動画はAAC 384kbps。

| 曲・方式 | 20〜150Hzの変化 dB | 8〜20kHzの変化 dB |
| --- | --- | --- |
| メタル / 従来 | +1.75 | -0.11 |
| メタル / FT差し引き | -1.67 | +0.25 |
| メタル / RoFormer CUDA | -2.50 | +0.04 |
| ラップ / 従来 | +0.69 | +0.45 |
| ラップ / FT差し引き | -1.39 | -0.94 |
| ラップ / RoFormer CUDA | -1.37 | -0.90 |

FFT4096、周期Hann、2048サンプル間隔で左右の帯域パワーを平均し、原曲と出力の全体RMS差を補正した。原曲には歌声も含まれ、除去そのものでも帯域が変わる。楽器の保持率・SDR・音質の合格点ではない。正解の独立した伴奏がないためSDR/SI-SDRは算出していない。

添付した4Kカラオケ2本は各28.000秒、2,080,868 / 2,142,761 bytes、AAC/48kHz/stereo。true peakは両方-3.1dBFS。元のキー・速度を保つ複合波形と、字幕修正後の48kHz・23kHz保持をテストする。自動検査だけで実曲の聴感合格にしない。

## 字幕の表示と限界

正本のTXT、時刻付きLRC、単語時刻JSONを受け取り、貼り付けとUTF-8歌詞ファイルに対応。歌詞がない場合のwhisper.cppはこのPCで候補を作り、正本とは扱わない。

- メタルの叫び声は文字起こしと英語CTCの全曲同期が不十分だった。CTC平均確信度は0.03、分離後の区間でも約0.23。アプリは0.35未満を採用せず、正本を残して修正を求める。サンプルは元動画の字幕を0.1秒間隔でOCR照合し、正本の行をLRCへ対応させた。単語ごとのスクリーム同期に合格したとは扱わない。
- ラップはWhisperのDTWを有効にした（Flash Attentionを切る必要があった）。約51%の正本の文字が認識結果と一致し、残りは同じ行内で補間した候補。無音や行間に字幕を早出ししない。全単語の±100ms精度は未検証。

英語CTCはRustのViterbiで既知の歌詞を音声の確率へ合わせ、単語時刻と確信度を保存する。低確信度を成功扱いせず、区間とViterbiで取り消しを確認。LRCの曲末の空行も受理する。

libassが1080p/4Kで文字を直接描画する。各5箇所でフレームを抽出し、表示・余白・時刻を確認。メタル11秒は元動画41秒付近と同じ「Go to ...」の行。ラップ5秒は「21歳の頃から...」の行。字が見えることと全単語の正確な同期は分けて扱う。

完成画面でLRCを直し、分離なしで新しい動画を作れる。原音・前の結果・正本を保持し、48kHzの伴奏を44.1kHzへ下げて字幕を直す経路を撤去した。同期失敗でも正本とエラー記録を保存し、字幕未確定を表示する。

## 製品の狙いと聴いて確認すること

カラオケに少ないメタルやヒップホップを自分のPCで練習するアーティストとファンを対象にする。重い歪み・低音・速い言葉を実例として維持する。正本と修正可能な時刻、高音質モデル、不要な加工の回避、原音の帯域、高解像度の文字、分離を繰り返さない修正が今回の差分。

音質の優位を断定せず、本人に確認してもらう。

1. 声が歌う邪魔になるほど残っていないか。
2. ギターが薄くなったり、不自然にシャリシャリしていないか。
3. キックと低音が痩せたり、揺れたりしていないか。
4. つなぎ目にクリックやざらつきがないか。
5. 字幕で歌い出せるか。早い・遅い箇所を秒数で指せるか。
