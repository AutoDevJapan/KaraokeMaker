# 保存済みの歌詞時刻を取得・取り消す

PC内の既存HTTPサーバーに、時刻編集画面から利用する取得・取り消し経路を用意している。画面の配置や操作ボタンはこの変更に含まない。

- `GET /jobs/{id}/timing` は完成した結果の `duration`（秒）、`lines`（各行の `start`・`end`・`text`）、`can_undo` をJSONで返す。時刻は速度変更後の再生音声に対応する。
- `POST /revise/{id}` は既存のフォーム形式で `csrf`・`lyrics`（LRC）・`preset` を受け取り、修正した別の結果を作る。終了時刻はLRCの空行で表す。重複・範囲外などの不正な時刻は処理の失敗として残る。
- `POST /undo/{id}` はフォーム形式で `csrf`・`preset` を受け取り、保存済みの編集履歴を1段戻した別の結果を作る。戻す前の状態を履歴に積み直さない。

POSTの受付後は `303` で `/jobs/{新しいid}` へ移動する。再出力や履歴読込に失敗した場合は、その結果の失敗理由を確認する。CSRF不一致は `403`、処理枠の使用中は `409`。Host・Originの検査も既存の操作と共通である。

原結果の音声・設定・履歴は変更しない。伴奏の分離は繰り返さず、LRC・ASS・SRT・動画と残る履歴を新しい結果へ保存する。アプリを再起動しても同じ結果IDで時刻と履歴を取得できる。読込中・再出力中の原結果は削除できない。

歌詞だけを修正した結果の `settings.json` は、再利用した伴奏の `separation` を原結果から引き継ぐ。ASRは実行しないため `automatic_subtitles` は `false` にする。音声はすでにキー・速度を調整済みなので、新しい結果の `key` は `0`、`tempo` は `1` とし、同じ調整を重ねない。最初のキー・速度と原設定は変更しない原結果に残る。これらの保存値は、別の分離モデルやASRを実行した証拠にはならない。

旧結果に履歴がない場合の取得は、その設定に保存された歌詞を元にする。保存済み履歴が破損している場合、曲長が違う場合、版や容量が不正な場合は元の歌詞へ置き換えずエラーを返す。取り消し可能な履歴がなければ再出力は失敗し、原結果を保持する。

英語歌詞のCTC時刻候補では、単語間の区切りラベル `|` を発声する文字へ含めない。区切りはCTC経路の計算に残すが、その滞在フレームを次の単語の開始・終了・文字の確信度へ加算しない。長い区切りの後でも、次の単語の時刻はその文字に対応するフレームから求める。この変換の整合性だけで、実曲の声との±100ms同期を確定しない。
