本書は今後の仕様です。一貫した自動制作が動作しているという報告ではありません。[Issue #12](https://github.com/AutoDevJapan/KaraokeMaker/issues/12)で管理します。

## 反映した構想

2026-10-04 22:49:55（日本時間、13:49:55 UTC、投稿1556302353685287045）のオーナー投稿を反映します。

作詞・作曲・MV・SNS投稿・マーケティングをひとつの作品から進め、歌詞、MIDI、WAV、パラレル編集を扱います。歌詞と曲調に合う映像を生成し、Netflix VOIDを編集候補にします。公開先はX・YouTube・TikTok・Instagram。Blaze・Accomplish・HyperAgents・TRIBE v2を活用する構想も採用候補として残します。


原文:

> 作詞、作曲、MV作成、SNS投稿、マーケティングを一貫して実行できるプラットフォーム。
> 歌詞の編集、曲の編集(MIDI, .wav, パラレル)、MV作成(歌詞や曲調に合わせた動画生成、Netfilx-Voidを使った動画編集)、SNS投稿(X,YouTube,TikTok,Instagram)、マーケティング(BlazeやAccomplishやHyperAgentsとTribeV2を組み合わせて人間心理に基づいたマーケティング)

「パラレル」は、当面、歌声や楽器など複数のトラックを並行して編集する意味として設計します。原文も保存し、意味が異なる場合はこの解釈を更新できます。

既存のSuno・JIZURA、AI-VTuberの担当キャラ、完成曲からのMV制作、後日のカラオケ公開という計画も維持します。カラオケ公開までの時間は変更可能にし、24時間を必須にしません。出品はADJで実曲の有用性を確認してから進めます。

## 作品を中心にした制作

1. 目的・ジャンル・届けたい相手・担当キャラを決め、作詞案を作る。
2. 歌詞を編集して採用する。その版からSuno用の雰囲気と曲候補を作る。
3. 試聴して曲を選び、取得した完成音源と提供された各トラックを作品へ登録する。
4. MIDI・WAV・複数トラックを編集し、採用する音源の版を決める。
5. 採用音源と歌詞からシーン計画と歌詞の時刻を作り、JIZURAへの受け渡しを設計する。キャラの歌声の指定と、MV内での担当は別の機能として扱う。
6. 映像を生成・編集し、歌入りMV、カラオケ版、媒体別の短い動画を作る。
7. 投稿先・公開範囲・時刻が指定された完成素材をSocialPilotへ渡す。
8. 公開URLと成果を作品に紐付け、次の制作へ反映する。

KaraokeMakerは作品・素材の版と書き出しを管理します。JIZURAへの接続は映像の生成・編集結果を返します。SocialPilotは媒体別の投稿と成果取得を担当します。投稿の実装を作品側へ重複して持ちません。

作品には、作品ID、目的、届けたい相手、媒体別の投稿文と訴求、歌詞の版、元音源、各トラック、採用した曲候補、完成音源の版、シーンと時刻、担当キャラ、書き出した素材、投稿先識別子、公開URL、分析結果とその日時を保存します。認証値を作品データへ含めません。採用した依存先の固定版と条件は `docs/dependencies.md` へ記録します。

SocialPilotの現状は[SocialPilotのREADME](https://github.com/AutoDevJapan/SocialPilot/blob/main/README.md)と、このPCの同リポジトリを確認した結果です。

原本は上書きしません。字幕の修正で音源分離を繰り返さず、音源の長さが変わった場合は歌詞の時刻と映像を再確認します。MIDIを提供しない生成サービスから、MIDI取得済みと表示しません。音源からMIDIへ変換する機能は別の推定結果として扱い、メタル・ラップでも音符・テンポ・各パートを検証します。

## 指定ツールの用途と確認事項

確認日: 2026-10-04。以下は一次資料による調査であり、インストール・契約・実行済みではありません。

| 候補 | 確認した用途と、この計画での扱い |
| --- | --- |
| Netflix VOID | 物体と、その物体が周囲に及ぼす影響を映像から除去するモデル。不要物の除去など特定の工程の候補。カット・字幕・音楽同期は別の編集機能で行う。公式手順はPython、マスク生成にGemini API、試用例は40GB以上のVRAM。Rustでの実行、マスク、GPUメモリ、依存モデルの条件を検証してから採用する |
| Blaze | ブランドに沿うコンテンツ、投稿管理、成果を踏まえた改善を提供するサービス。既存契約、OAuth連携、追加費用を確認し、未契約のサービスを自動で購入しない |
| Accomplish | 指定に近い旧公開リポジトリはCoworkerへ転送され、サポート終了と表示。現在の公式サイトは新サービスの先行案内。フォークを現行の公式製品と扱わず、対象の版とOAuth経路、制作データ管理への適性を確認する |
| HyperAgents | タスク担当と、その担当を改善するエージェントを持つ研究実装。公式手順はPythonとAPIキー。公開実装をそのまま稼働させず、Rustと既存OAuth接続で投稿案を評価・改善する設計を検討する |
| TRIBE v2 | 動画・音声・文章から平均的な被験者のfMRI反応を予測する。公開ライセンスはCC BY-NC 4.0で、公開実装はPython。Rustでの実行経路も検証対象。視聴維持率や購買意欲の測定と区別し、商用組み込みには利用条件の解決が必要。中核の分析は実際の投稿成果で進める |

一次資料:

- [Netflix VOIDの説明と実行条件](https://github.com/Netflix/void-model)、[コードのライセンス](https://github.com/Netflix/void-model/blob/main/LICENSE)。コードの条件だけで依存モデルの条件を確定しない。
- [Blazeの提供機能](https://www.blaze.ai/)。契約前に最新の費用と条件を確認する。
- [Accomplishの旧公開リポジトリの転送先](https://github.com/accomplish-ai/coworker)、[現在の公式サイト](https://www.accomplish.ai/)。
- [HyperAgentsの実装](https://github.com/facebookresearch/HyperAgents)、[研究論文](https://arxiv.org/abs/2603.19461)。
- [TRIBE v2の説明](https://github.com/facebookresearch/tribev2)、[ライセンス](https://github.com/facebookresearch/tribev2/blob/main/LICENSE)。

## 作る順序と受け入れ条件

| 段階 | 確認する結果 |
| --- | --- |
| 1. 作品管理 | 歌詞・曲候補・音源・MV・投稿記録を1作品で開ける。再起動後も採用した版を取り違えない |
| 2. 作詞・選曲 | サブスク枠で作詞し、採用歌詞からSunoで生成・試聴・選曲までを1曲で確認する |
| 3. 音源編集 | WAVと各トラックを編集・試聴・書き出しできる。MIDIの入力・編集・音源化を区別して確認する |
| 4. MV・カラオケ | 採用音源、歌詞の時刻、担当キャラから短いMVとカラオケ版を作り、音質・字幕・4K表示を実出力で確認する |
| 5. 公開・分析 | 指定された1媒体・1投稿から送信結果を照合し、取得可能な視聴維持・クリック等を次の案へ反映する |

認証は既存のOAuth接続に委ねます。APIキーによる呼び出しとPythonの新規実装・実行は行いません。ブラウザはログイン済みのオーナーのChromeを使い、通常の画面と提供された連携機能を使い、認証ファイルやCookieの保存ファイルを読みません。自分で開いたタブを終了時に閉じます。専用プロフィールへログインし直す現在のSuno接続方式は移行対象です。

外部で生成する素材は利用者が選んだものだけです。カラオケ変換に使う音楽・動画・歌詞・生成物はPCで扱い、外部AIへ送りません。Suno等で新規制作する作品は音楽制作の領域として区別し、その利用者が選んだ歌詞・素材だけを外部生成へ渡します。公開はオーナーが指定した投稿先と公開範囲に従います。送信結果が不明なときは媒体側で照合し、二重投稿を避けます。各媒体の接続条件はSocialPilot側で検証します。
