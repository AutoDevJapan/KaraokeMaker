# 保存したテンプレートで動画を出力する

制作者向けCLIの `render` と `convert` は、`--template <JSON>` と `--project <案件ID>` を受け付ける。既存の画面へ新しい設定欄を追加する機能ではない。`render` は許可済みの完成音源や伴奏へ字幕を付け、音源分離を繰り返さずに出力する。

## ファイルを作る

UTF-8のJSONを、案件の編集用フォルダへ保存する。以下は背景色だけを使う例。

```json
{
  "version": 1,
  "project": "project-a",
  "style": {
    "background": "142e27",
    "accent": "ceffa4",
    "font": "Yu Gothic"
  },
  "background_image": null,
  "logo": null,
  "horizontal_margin": 0.1,
  "vertical_margin": 0.1,
  "max_lines": 2
}
```

| 項目 | 意味 |
| --- | --- |
| `version` | 現在は1。未対応の版は拒否する |
| `project` | `--project` と完全一致する案件ID。別案件のテンプレートの誤指定を拒否する。空文字は不可 |
| `style.background` / `accent` | 背景色・字幕強調色の6桁RGB（`#`なし） |
| `style.font` | PCに導入されたフォント名。選択できない場合はFFmpeg/libassのフォールバックを使うため、出力も確認する |
| `background_image` / `logo` | `null`、またはPC内の素材の絶対パス。例：`C:/Projects/project-a/assets/background.png` |
| `horizontal_margin` | 横長の出力で使う余白割合（0〜0.4） |
| `vertical_margin` | 縦長の出力で使う余白割合（0〜0.4） |
| `max_lines` | 一度に表示する字幕の最大行数（1〜4） |

余白はX/Y別の設定ではなく向き別。選んだ割合を左右は画面幅、上下は画面高へ適用する。組込みのプラットフォーム安全領域より狭くしない。題名・字幕の明示位置と手動回避矩形は、[位置保存の追加機能（PR37）](https://github.com/AutoDevJapan/KaraokeMaker/pull/37)で扱う。

案件IDの一致は素材自体の所属や権利を証明しない。指定した画像・ロゴがその案件の素材であり、利用許可があることは利用者が確認する。

素材は許可済みのPNG/JPEGだけを使い、絶対パス・拡張子とファイル先頭の形式を照合する。画像を一度復号して繰り返し、元画像は変更・アップロードしない。別案件の素材とAI生成イラストは納品素材に含めない。ファイルが元の絶対パスに残っていることが再出力の前提で、移動した場合は参照先を正規の案件素材へ直す。

## コマンド例

```powershell
./karaoke-maker-cli.exe render ./approved-audio.wav --output ./results --title "曲名" --lyrics ./song.lrc --preset 1080p --background --template ./template.json --project project-a
```

縦1080pは `--preset vertical`。`--background` は元動画ではなく背景画像・背景色を使う指定。`convert` も同じテンプレート指定に対応するが、音源分離が必要になる。テンプレートを使う場合の色・フォントは `template.style` から取り、別の `--style` は使わない。

出力先の下へ新しい結果フォルダを作る。再利用するテンプレート・案件IDは `settings.json` に保存され、字幕改版時も引き継ぐ。旧結果にテンプレートの項目が無ければ、従来設定を使う。元の音源や以前の結果を上書きしない。

## 折返し・拒否・検品

字幕は出力と同じFFmpeg/libassで、指定フォント・太字・縁取りの実描画を計測する。Fontsizeと文字数の固定係数だけでは幅を判定しない。長い語を複数行へ表示する場合は、各表示部分に元の語の時間を配分する。空白や元の語時刻を失わないように扱い、行数に収まらなければ拒否する。

初回の計測は歌詞の量によって数分かかることがある。Windows・Yu Gothic・デバッグ版の動作確認では、40行のLRCで約73秒、300語の語単位字幕で約170秒だった。Webの結果画面では計測中の段階を進捗に表示し、CLIの `render` / `convert` は処理開始前に待ち時間の案内を標準エラーへ出す。CLIの標準出力は従来どおり結果フォルダーのパスだけである。同じアプリ起動中の同じ文字列・フォント・サイズ等の計測はキャッシュを再利用するが、初めて使う歌詞やアプリ再起動後は計測し直す。これらはその環境での実測で、全PCの所要時間や高速化を保証する値ではない。

ロゴは安全領域の右上へ配置し、縦横比を保って領域幅の25%・画面高の10%の両方へ収める。字幕はその後に描画する。実際の文字幅は導入済みフォントやフォールバックによって変わるため、他のPCへ移したら横縦の出力を再確認する。日本語表示には日本語を収録したフォントが必要。

設定の検査や自動の画素検査は、全編の試聴・字幕目視の代わりではない。[制作と納品の検品手順](production-workflow.md)に従い、顔・字幕・ロゴ・配信先の表示領域を含めて確認する。設定ファイルには案件IDと素材の絶対パスが含まれるので、そのまま公開しない。
