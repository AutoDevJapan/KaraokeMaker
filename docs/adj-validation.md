# ADJで有用性を確かめてから出品する

オーナーの2026-10-04 17:42:58（日本時間）の指示を優先する。出品・販売の公開と受注は、ADJで用途を確認するまで進めない。価格の案があることを販売開始の承認とは扱わない。

## 目的

当初の目的はカラオケに収録されていない曲を個人で歌うこと。まずこの用途で、音源を入れて伴奏と歌詞映像を作るまでを確かめる。自作曲から歌入りMVとカラオケ版を作る制作用途も、別の試験として扱う。

## 確認すること

| 試験 | 確認内容 | 出品前の条件 |
| --- | --- | --- |
| 歌声と伴奏の分離 | 主旋律の歌声、コーラス、残る響き、伴奏の欠けを原本と比較する | ADJ内で試聴し、歌う邪魔になる残りや伴奏の大きな欠けがないこと |
| 実際に歌う | 曲頭・歌い出し・間奏・曲末と、キーを変えた場合を試す | 歌い出しと拍を追え、本人が使えると評価すること |
| 字幕 | 日本語、長い行、間奏、時刻修正、横と縦の安全領域を確かめる | 読めない文字や顔に重なる表示がなく、修正後の時刻が一致すること |
| 出力と手間 | 読み込みから完成までの時間、やり直しの時間、容量を実測する | 作業に必要な待ち時間と修正手順が明確であること |
| 安定性 | 取り消し、再起動、失敗後のやり直し、原本の不変を確かめる | 原本が変わらず、失敗や重複が分かること |

権利のある実曲を複数使い、独唱とコーラス・密な伴奏を分けて結果を残す。分離前の正解の伴奏・歌声が入手できれば、原本と分離結果を数値と試聴で比較する。正弦波や動くテスト画像による書き出し試験だけで、歌声の分離品質や歌いやすさを合格としない。

## 個人用としての合格条件

3分程度の曲で、音源を選ぶ・解像度を選ぶ・作成・再生の順に進め、処理待ちは10分以内を目標とする。歌詞の正本がある場合の時刻修正は15分以内を目標とし、本人の歌唱時に開始ずれ±100msを目安に許容できること。行単位の色変化で練習できるかも本人が判断する。速度・キー調整を重ねず、曲末・間奏まで歌えること。字幕が読め、伴奏の音が歪まず、声残りや楽器欠落が歌う邪魔にならないこと。数値は本仕様の目標で、未計測の手作業時間を実績として扱わない。

Ryzen 9 9950X3D、RTX 5090、FFmpeg 8.0.1。最初の3曲はGPUを含むdebug CLI、4曲目は同じビルドのWeb読み込み経路。時刻は読み込み・分離・WAV/MP3/MP4出力を含む。初回モデル取得は、導入済みのハッシュ検証付きモデルをコピーしたため含まない。GPU処理は自分の試験では1曲ずつ直列。PCの他処理と初回シェーダー準備の影響があるため、専用GPUの速度保証ではない。

4曲とも原本のSHA-256が不変。曲末と出力長の差は0.01秒未満。4Kの実曲は3840×2160、H.264/yuv420p、30fps、AACを確認した。字幕の候補を入力して画面のボタンで作り直した4K動画は71.23秒、6,689,978 bytes。元の伴奏のSHA-256が不変で、音源分離を繰り返さずに修正版が別の結果として残った。

ブラウザーで解像度の選択・処理中の区間表示・完成後のプレイヤーと保存リンク・字幕修正を確認した。ファイル選択の自動操作では入力が空になったため、4曲目の開始は同じWebフォームのmultipartをHTTPで送った。ファイル選択からの全クリック操作を合格済みとは扱わない。本人が自分で1曲を選ぶ確認を残す。作業で開いたChromeタブと試験サーバーは終了する。

## 分離の数値と限界

whisper.cpp 1.9.2、large-v3-turbo-q5_0、英語、CPU4スレッドを使い、同じ条件で元曲と伴奏をPC内で認識した。認識語数と3語連続の一致を比較した。

| 曲 | 原曲の認識語数 | 分離伴奏の認識語数 | 同じ3語連続の一致数 |
| --- | --- | --- | --- |
| There Ain't Nothin | 0 | 36 | 0 |
| How Can Things Be | 33 | 25 | 0 |
| Halloween | 201 | 25 | 0 |
| Me And God | 258 | 27 | 0 |

この指標は声の残りの候補確認で、音質や歌いやすさの合格点ではない。「Thank you」等の反復や、楽器だけの箇所を歌詞として認識する例が出た。There Ain't Nothinは元曲に歌詞を認識できず、歌声除去の評価曲として数えない。How Can Things Beの認識された声も少なく、歌唱曲としての評価の中心はHalloweenとMe And God。声残りを確認する比較にはMe And Godの同じ10〜20秒の区間を用意した。正解の伴奏ステムを取得できていないため、SDR等の分離精度と楽器欠落の程度は未計測。

字幕候補はASRであり、原曲の正式な歌詞・手動で確定した時刻ではない。実曲で±100msの歌詞精度を達成したとは主張しない。LRCの開始時刻がASS/SRTへ正しく変換されること、空行で間奏表示が終わること、4Kでフォントが直接描画されることは実出力とテストで確認した。自動認識だけで歌うための歌詞を完成させる機能は未実装。

## 最も弱かった点と修正

1. 完成後の字幕修正をCLIで行う必要があった。完成画面にLRC修正欄と「歌詞だけ直して動画を作る」を追加した。画面の時刻は調整済み伴奏の時刻に合わせる。キー・速度を二重適用しない。横・縦4Kを含む解像度選択も画面へ反映した。
2. 旧版の音量制限だけではtrue peakが高すぎた。Halloweenの旧WAVで+0.8dBFSを測定した。新しい処理はWAVのtrue peakを測り、必要なときだけ単純な音量低下で-3.1dBTP付近の余裕を確保し、MP3/AACのピークも0dB未満を確認する。強弱を平坦にする自動マスタリングは行わない。

| 曲 | 修正後の再出力秒数（分離なし） | WAV / MP3 / MP4のtrue peak dBFS |
| --- | --- | --- |
| There Ain't Nothin | 42.84 | -3.1 / -3.1 / -3.0 |
| How Can Things Be | 52.58 | -3.1 / -3.1 / -2.9 |
| Halloween | 44.65 | -3.1 / -3.1 / -2.0 |
| Me And God（4K、字幕候補） | 66.16 | -3.1 / -3.2 / -3.1 |

元曲の読み込みからの初回時間と、ピーク修正後の再出力時間を混ぜない。再出力は同じ分離済み伴奏を使用し、分離を再実行していない。測定にはdebugビルドを使った。音量修正後の4Kは6,749,099 bytes。実曲の伴奏品質に合格したという判断はまだない。
